Ubuntu 무선 네트워크 설정

이 메모를 처음 썼을 때는 iwconfig, ifconfig, iwlist로 무선 인터페이스를 찾고 /etc/network/interfaces에 wpa-ssid, wpa-psk를 적는 방식이 흔했다. 지금은 설치 환경에 따라 NetworkManager 또는 Netplan이 네트워크를 관리한다. 같은 인터페이스를 두 도구에서 동시에 설정하면 어느 설정이 적용됐는지 헷갈릴 수 있으므로 현재 관리 방식을 먼저 확인한다.

인터페이스와 AP 확인

ip link                     # 인터페이스 이름 확인
nmcli device status         # NetworkManager가 장치를 관리하는지 확인
nmcli device wifi list      # 보이는 무선 AP 목록

원래 메모의 wlan0은 예시 이름일 뿐이다. 실제 장치는 wlp...처럼 다른 이름일 수 있다. nmcli device status에서 무선 장치가 보이고 NetworkManager가 관리한다면, 다음처럼 대화식으로 연결할 수 있다.

nmcli --ask device wifi connect "AP_이름"
nmcli connection show --active
ip address

--ask는 비밀번호가 필요할 때 입력을 요청한다. 셸 명령줄에 비밀번호를 그대로 쓰지 않아도 된다. NetworkManager의 nmcli 예제에 AP 검색과 연결 방법이 나와 있다.

고정 주소가 필요할 때

기존 메모는 DHCP(iface ... inet dhcp)와 수동 주소(inet static)를 나눴다. 이 구분은 지금도 유효하다. DHCP는 주소·게이트웨이·DNS를 자동으로 받고, 고정 주소는 현재 네트워크의 주소 대역과 게이트웨이를 확인한 뒤 지정해야 한다. 예전 예시의 192.168.0.2와 192.168.63.1을 실제 환경에 그대로 복사하면 서로 다른 주소 대역 때문에 연결되지 않을 수 있다.

Netplan을 쓰는 시스템이라면 /etc/netplan/*.yaml의 무선 장치, dhcp4, access-points, 필요 시 addresses·경로·DNS 항목을 설정한다. Netplan 무선 설정 예제를 현재 설치 버전에 맞춰 참고한다. 원격 장비의 네트워크 설정을 바꿀 때는 적용 후 되돌릴 수 있는 netplan try를 사용하고, 비밀번호가 든 설정 파일은 공개 저장소에 올리지 않는다.

연결이 안 될 때

  1. ip link로 인터페이스가 보이는지 확인한다. 보이지 않으면 드라이버나 무선 장치 인식부터 살펴본다.
  2. nmcli device wifi list에 AP가 보이는지 확인한다. 보이지 않으면 거리, 무선 차단, 주파수 대역을 점검한다.
  3. 연결됐는데 인터넷만 안 되면 ip route로 기본 경로를, resolvectl status로 DNS 설정을 확인한다.

예전의 ifdown wlan0·ifup wlan0은 /etc/network/interfaces를 사용하는 환경의 명령이다. NetworkManager나 Netplan이 관리하는 인터페이스에 그대로 적용하지 않는다. 문제가 생겼다고 /etc/rc.local에 임의의 활성화 명령을 추가하기보다는 먼저 실제 네트워크 관리자를 확인하는 편이 원인을 찾기 쉽다.

연결 절차를 단계별로 보기

무선 연결은 한 번에 끝나는 작업처럼 보여도 장치 인식 → AP 검색 → 인증 → IP 주소 할당 → 경로·DNS 설정으로 이어진다. 어느 단계에서 실패했는지 알아야 비밀번호를 반복해서 바꾸거나 DNS만 고치는 일을 줄일 수 있다.

flowchart LR
  장치[무선 장치 인식] --> 검색[AP 검색]
  검색 --> 인증[암호화 방식·암호 확인]
  인증 --> 주소[DHCP 또는 고정 IP]
  주소 --> 경로[기본 경로]
  경로 --> DNS[이름 해석]
증상먼저 확인할 부분해석
ip link에 무선 장치가 없다하드웨어 인식·드라이버·가상 머신 무선 장치 전달AP 설정 이전 문제
장치는 있지만 AP가 안 보인다nmcli radio wifi, 거리·대역, 숨김 SSID 여부검색 단계 문제
AP는 보이나 연결이 실패한다인증 방식·비밀번호·공유기 접근 제어인증 단계 문제
연결됐지만 IP가 없다DHCP 서버·주소 풀·연결 프로필주소 할당 문제
IP 통신은 되는데 도메인이 안 열린다ip route, resolvectl status경로 또는 DNS 문제

실제 사용 장치에 NetworkManager가 연결 프로필을 만들었다면 nmcli connection show --active에서 프로필과 장치를 함께 확인한다. 여러 Wi-Fi 프로필이 저장돼 있다면 엉뚱한 AP에 자동 연결됐을 수도 있다. nmcli device wifi rescan 뒤 다시 목록을 확인하고, 인증에 실패했다면 저장된 연결 프로필의 설정을 살펴본다. 명령줄에 암호를 직접 쓰면 셸 기록이나 프로세스 인수에 남을 수 있으므로 앞의 --ask 방식을 우선한다.

Netplan을 쓰는 무선 서버의 예

NetworkManager가 없는 서버에서는 Netplan의 wifis 설정을 검토할 수 있다. 다음은 DHCP를 사용하는 구조 예시이며, 실제 인터페이스 이름과 인증 정보를 확인해 입력해야 한다. 설정 파일에 암호를 적는 방식은 파일 접근 권한과 백업·버전 관리 경로까지 함께 관리해야 한다.

network:
  version: 2
  renderer: networkd
  wifis:
    wlp2s0:
      dhcp4: true
      access-points:
        "my-wifi":
          password: "설정할-실제-암호"

원격 무선 장치에 적용하기 전에는 콘솔 접속 수단을 준비하고 sudo netplan generate로 구문을 검사한 뒤 sudo netplan try로 연결이 유지되는지 시험한다. IP를 수동으로 지정한다면 주소만 넣지 말고 기본 경로와 DNS까지 설정해야 한다. 무선 연결이 자주 끊기는 환경에서는 재연결 횟수와 AP 신호 품질, DHCP 임대 시간을 같이 기록해야 장치 문제와 주소 할당 문제를 구분할 수 있다.

NetworkManager의 nmcli 명령 설명과 Netplan 무선 설정 예제를 참고한다.
